# QingYin 前端设计稿规范

版本：v0.2
状态：仅设计，不进入前端实现

## 1. 目标

前端是开发者与运营控制台，不做营销落地页。先以设计稿冻结信息架构、状态、数据密度和权限边界，再由已确认稿驱动实现，避免实现阶段自行发挥。

目标用户：开发者配置 API 与调试会话；运营人员管理 Provider、成本和告警；管理员管理租户与密钥。

## 2. 设计稿画板

| 画板 | 主任务 | 必须覆盖的状态 |
| --- | --- | --- |
| 概览 | 查看会话、质量、成本、Provider 健康 | 正常、告警、无数据、加载 |
| 实时调试台 | 录音/上传、观察 ASR/TTS 事件与时延 | 未授权、连接中、active、busy、错误、完成 |
| Provider 目录 | 比较能力、启停、查看准入状态 | healthy、degraded、open、pending verification |
| 路由策略 | 定义 profile、候选顺序、local-only | 草稿、预览差异、发布确认、回滚 |
| 音色与模型 | 管理可用声音、缓存和本地模型版本 | 无权限、下线、版本回滚 |
| 用量与配额 | 分租户查看实时用量、成本估算、上限 | 低余量、超额、估算待对账 |
| 质量分析 | 比较 Provider/模型/策略的在线与离线质量趋势 | 数据不足、质量门失败、报告计算中 |
| API 密钥 | 创建、限制、轮换、撤销 | 密钥仅展示一次、空状态、已撤销 |
| 审计与事件 | 查询高风险操作和故障时间线 | 筛选、导出权限不足、无结果 |

桌面先按 1440px 宽度设计，移动只覆盖概览、调试台和告警确认等必要任务；不能简单缩放桌面表格。

## 3. 信息与交互原则

- 页面第一屏展示当前可行动的信息：异常 Provider、带宽水位、活跃流、配额风险，而不是品牌宣传。
- Provider 表格固定展示：任务、流式能力、数据面、P95、错误率、并发、成本估算、准入状态。
- 路由策略发布采用“差异预览 -> 风险提示 -> 二次确认”，不能即时无提示覆盖生产策略。
- 调试台事件按 Canonical Event 渲染，附原始 Provider 诊断仅对有权限角色可见。
- 音频播放以播放器、波形/进度、音频格式状态表达；不把二进制/长日志直接堆到主页面。
- 所有异常都给下一步动作，例如切换 Direct、等待配额、重试会话或查看故障事件。

## 4. 设计交付与验收

设计稿使用组件变量定义颜色、间距、文字层级、表格、状态标签、图表、图标按钮和对话框。每个关键画板必须附带：交互连线、加载/空/错误状态、权限差异、最长字段溢出规则、桌面与移动断点。

确认门：先确认导航、概览、调试台、Provider 目录和路由策略五张主画板；随后才允许创建前端工程。实现验收以已确认画板逐屏比对，不得以“前端方便”为理由改变核心流程。
