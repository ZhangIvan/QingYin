# QingYin 测试验收与发布计划

版本：v0.2

## 1. 测试层级

| 层级 | 对象 | 必测内容 |
| --- | --- | --- |
| 单元 | Canonical 类型、路由评分、限流、错误映射 | 边界值、未知枚举、策略冲突 |
| 契约 | Gateway、SDK、Adapter | JSON/AsyncAPI fixtures、事件顺序、取消 |
| 集成 | 真实沙箱 Provider、Local Worker | 鉴权、音频格式、真实流、配额错误 |
| 准入 | 每个候选 Provider | 模块 09 的能力快照、探针、成本与安全审查 |
| 韧性 | Gateway/Worker/网络 | 断链、超时、熔断、背压、重复请求 |
| 性能 | 目标 ECS、目标网络 | 空闲连接、Relay、Local、缓存分发分别压测 |
| 安全 | 凭证、日志、租户隔离 | 无长期密钥下发、local-only 不出云、越权失败 |
| 恢复 | Gateway、状态存储、配置与 Provider | RTO/RPO、备份恢复、实例/地域/Provider 故障演练 |

| 质量报告 | Provider、模型、策略与路由 | 语料/采样版本、计算复跑、趋势、质量门和权限隔离 |

## 2. 版本验收门

### M1 核心骨架

- 统一协议 fixtures 在 Gateway、Mock Adapter 和 SDK 中全部通过。
- `cancel` 在 1 秒内终止 Mock/Worker 任务并释放会话许可。
- 任何未知事件/字段不会导致进程崩溃或静默丢弃关键错误。

### M2 云接入

- 至少一个主、一个备云 Provider 通过 ASR 或 TTS 的全链路探针。
- Provider 失败在允许的会话边界内按文档退化，不能造成无上限重试。
- Relay 在带宽 75% 水位自动拒绝新流；Direct 会话没有 Gateway 音频转发。

### M3 本地模型

- Local-only 请求网络审计中没有云访问。
- 本地模型满载在 100 ms 内按策略转云或 busy；`local_only` 只能 busy，绝不转云。
- 目标机压测报告包含 RTF、TTFB、P95/P99、RSS、CPU、带宽和失败原因。

### M4 多厂商与运营

- 每个已启用 Provider 都有能力探针、错误映射、熔断、成本记录和回滚开关。
- 每个生产环境均有模块 10 的容量卡和经压测确认的能力声明；资源、模型、编码或配额变更后旧声明自动失效。
- OpenAPI/AsyncAPI 兼容检查、模块 14 威胁模型审查、模块 15 过载降级测试均已通过，且没有未关闭的 P0 风险。
- 模块 16 至 19 的状态一致性、账务对账、SDK 安全和 Admin 工作流测试均已通过，且控制台只依赖已脱敏、可授权的数据契约。
- 租户、环境、密钥、用量和审计隔离经自动化测试验证。
- 告警、故障演练、发布回滚全部有可复现记录。

## 3. 初始 SLO 与容量判定

初始体验目标：ASR 首个 partial P95 小于 500 ms，VAD 后 final P95 小于 1000 ms；TTS 首个音频 P95 小于 800 ms，分段 gap P95 小于 120 ms；实时队列等待 P95 小于 100 ms。它们是验收目标而非合同 SLA，任何数字必须随 CPU、模型、区域和 Provider 具体化。

任意部署规格的验收不以“支撑多少推理路数”一句话定义：

1. 先由容量模型录入 CPU、内存、入/出带宽、模型实测 CPU 时间与 Provider 配额，再分别压测空闲连接、Direct 控制会话、Relay 压缩流、Local ASR、Local TTS 和缓存下发。
2. 逐级增加活跃流，出现 CPU P95 超过 75%、带宽超过 75%、SLO 失守或错误率上升时回退一级。
3. 将回退前一级写入该环境的容量报告和策略配置，路由配置不得超过它；更换资源规格、模型或 Provider 后必须重新计算并复测。

## 4. 发布与回滚

发布顺序：本地 mock -> 沙箱 Provider -> 内部租户 -> 小比例真实流量 -> 全量。Provider、模型和策略均支持独立开关；回滚优先切换路由权重或关闭 Adapter，避免重启 Gateway 影响已有会话。

每次发布保留：版本、配置哈希、模型版本、Provider 能力快照、容量报告、变更人、演练结果和回滚结果。未达验收门的功能保持 `experimental`，不出现在默认策略中。
