## 2. 本轮纠正项

以下问题已在设计资产中修复，不能带入实现：

1. AsyncAPI 初稿只声明 ASR 收发操作，现已补齐 TTS 和 Realtime 的控制、二进制输入/输出和 operation 方向。
2. 管理面契约缺少乐观并发控制和变更原因，现对可变 Workspace 引入 `If-Match`、`Idempotency-Key` 和 `X-QingYin-Change-Reason`。
3. Operation、容量卡状态枚举与模块 19 存在差异，已统一为 `queued|running|succeeded|failed|cancelled` 及 `draft|review|active|stale|retired`。
4. 模块 19 的质量资源与质量权重工作流条目重复，已删除重复项。
5. 后台确认页面涉及的空间、质量、容量、版本、诊断和操作资源已建立 API 覆盖清单，禁止以厂商私有字段或日志查询补洞。

## 3. 进入实现前必须完成的外部验证

这些不是架构缺失，而是任何文档都不能替代的实证门槛。未满足时只能实现 MockProvider 和开发环境，不可上线真实业务：

| 外部验证 | 拦截范围 | 需要的证据 |
| --- | --- | --- |
| Provider sandbox probe | 该厂商进入 default/canary route | 账号权限、实时协议、临时凭证、配额、地域、成本、错误语义、限流和 TTS/ASR 测试记录 |
| 目标环境容量压测 | 发布并发数、套餐、限流上调 | 可复现负载、指标、P95/P99、断网/cancel、N+1 折减后的有效容量卡 |
| 安全/合规评审 | L4/L5 诊断、数据地域、客户数据留存 | 数据分类、DPA/授权、保留期、密钥管理、日志脱敏与删除演练 |
| 故障恢复演练 | 生产高可用声明 | RTO/RPO 测量、备份恢复、Provider 下线、密钥撤销、空间冻结记录 |
| SDK 互操作验证 | Direct 与移动端承诺 | 浏览器/iOS/Android/Server 的 ticket、重连、音频格式和事件兼容矩阵 |

## 4. 实现准入顺序

1. 使用 MockProvider 实现并测试首条 ASR/TTS 纵向切片，不连接未准入云厂商。
2. 完成一个主云 Provider 的 probe 和 Adapter contract suite 后，开启单环境、限额 canary。
3. 依据容量卡启用 Relay 生产限流；Direct SDK、本地 Worker 和第二 Provider 各自独立验收，不与基础切片捆绑。
4. 管理面按资源契约清单补齐接口后，再实现已确认的后台设计稿；前端每个页面必须走受控 API，而不是拼接日志或 Provider 控制台数据。

## 5. 冻结边界

可冻结：资源层级、租户边界、Canonical 事件、公开 API 名称和 v1 兼容规则、Provider trait 边界、实时链路不经队列、local-only 规则、容量计算方法、后台信息架构。

暂不冻结：主/备 Provider 选择、具体限流数值、每种硬件容量、具体成本、Direct SDK 范围、L4/L5 数据留存时长和合规选项。这些必须由对应的 probe、压测和安全评审产生版本化证据后冻结。

## 6. 设计阶段验收结论

设计包已经具备进入后端首条纵向切片的条件，且能承接已确认的三类后台页面：实时会话诊断、版本/路由与容量/质量、空间与成员管理。它不是生产系统本身；真正的生产验收必须以第 3 节的实测、演练和安全证据关闭后才能签署。
