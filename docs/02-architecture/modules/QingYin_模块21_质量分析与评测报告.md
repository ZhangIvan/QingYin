# QingYin 模块 21：质量分析与评测报告

版本：v0.2
目标：将“延迟正常”与“语音质量可靠”分开度量，为 Provider/模型/策略的启用、权重变化和回滚提供可重现证据，也为控制台提供脱敏的质量分析数据。

## 1. 三类质量信号

| 信号 | 数据来源 | 适用目标 | 不能替代 |
| --- | --- | --- | --- |
| 在线运行质量 | 实时指标、错误、partial 回改、chunk gap、用户取消 | 发现退化、验证 SLO、路由健康 | 真实准确率/MOS |
| 离线基准评测 | 已授权且有真值的固定语料、版本化模型/策略 | ASR CER/WER、标点、热词、语言、TTS 主观/客观质量 | 真实生产分布 |
| 受控质量采样 | 明确授权的匿名化/脱敏生产样本、人工标注、用户反馈 | 发现领域漂移、补充基准盲区 | 默认全量留存 |

没有真值的生产转写不得被包装为 CER/WER。没有方法、样本量和置信区间的单一评分不得直接提高 Provider 权重。

## 2. 指标字典

| 范围 | 指标 | 说明 |
| --- | --- | --- |
| ASR 准确性 | CER/WER、标点准确率、热词命中率、语言识别准确率 | 仅在带真值语料上计算 |
| ASR 稳定性 | partial revision rate、stable-prefix violation、final-update rate | 在线/离线均可计算 |
| TTS 体验 | first audio、audio RTF、chunk gap、取消后残留音频、断片率 | 运行质量 |
| TTS 自然度 | MOS/偏好胜率、发音错误率、韵律/音色一致性 | 人工或已验证自动评测，必须标注方法 |
| Realtime | turn latency、barge-in 成功率、端到端失败率、任务完成率 | 依赖产品定义的成功标准 |
| 系统质量 | Provider 错误、超时、SLO 达成率、容量拒绝率、回退成功率 | 不能单独代表语音效果 |

每个指标必须携带单位、方向、计算版本、时间窗、样本量、置信度/置信区间、过滤条件和数据来源等级。

## 3. 质量快照与质量门

`Quality Snapshot` 是不可变报告资产，最少引用：Provider Snapshot、Model Version、Policy Version、Capacity Card、地域、语言、codec、数据集/采样版本、评测方法版本、时间窗、指标、样本量、置信度与状态。

状态为 `draft|running|completed|insufficient_data|failed|superseded`。报告映射为质量门 `eligible|degraded|blocked`：安全、地域、准入、容量仍先于质量；数据不足只能维持保守权重；基准质量回退阻止提高权重；提升必须先经过路由模拟与 canary。

## 4. 管理面与前端查询

管理面提供 `quality_reports`、`quality_comparisons`、`evaluation_runs` 和 `quality_gates`。查询支持时间、任务、Provider、模型/音色、策略、地域、语言、codec、客户端平台和数据来源过滤。

前端展示趋势、样本量、置信度、报告状态、质量门、与基线差异和关联版本。前端不得默认显示原始音频、全文转写、人工标注或跨 Workspace 样本。

## 5. 数据治理与验收

基准语料必须具备来源、许可证、场景标签和版本。受控生产采样必须经过隐私开关、抽样比例、脱敏、访问审批和保留期限制。质量报告可复跑；质量门失败会阻止权重提升并产生审计告警；低样本或可能重识别个体的切片必须合并、延迟或拒绝展示。
