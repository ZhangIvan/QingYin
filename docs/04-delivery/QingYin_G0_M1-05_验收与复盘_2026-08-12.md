## 3. 已实现候选

- 六门顺序固定为 request rate、active sessions、gateway bytes、provider capacity、policy、budget，并覆盖每门拒绝与后续门补偿。
- admission 操作绑定完整租户、original actor、credential、principal digest、operation、reservation、request digest、session 和 exact generation。
- client cancel 仅允许 original actor；renew/release/settle/reclaim 仅允许租户匹配的 service account 与 `AdmissionManage`。
- commit/rollback 不确定结果返回 exact pending handle；compensated/expired/committed/terminal reconciliation 都携带并校验相同 identity。
- fake 覆盖精确过期、generation history/ABA、tenant-scoped budget/project capacity、renewal idempotency、终态冲突、bounded reclaim 和 release/settle race。
- security test fixtures 为封闭目录；release 及开启 debug assertions 的 release 均由非 debug Cargo profile guard 拒绝。

以上是候选实现描述，不是 GitHub 审批或生产能力证明。

## 7. 风险与阶段决定

- 工具链存在声明差异：workspace MSRV 是 1.85，固定 CI 是 1.97，本地候选是 1.93。关闭方式只能是新增 MSRV lane 或更新支持声明，不能将其中一个版本的结果泛化到另一个版本。
- admission pool/account/snapshot 类型是公开领域类型；M1-07 若允许客户端选择这些值，会产生容量分桶、预算和策略绕过风险，必须由 trusted server resolver 封闭。
- reclaimer correctness 已有 deterministic test，但调度延迟、积压公平性和真实 backend 性能尚无环境证据。
- 本轮没有真实 Provider、真实状态 backend、部署、容量、恢复或灰度证据，生产持续 `NO-GO`。

阶段决定：G0 / M1-05 保持 `VERIFYING`。允许继续本地收口、PR/CI/审阅和 M1-06/07 readiness；不允许启动 M1-06 合并实现，不允许进入 R2，不允许任何生产操作。
